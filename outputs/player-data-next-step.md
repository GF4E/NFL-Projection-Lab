# Evidence needed for the next player experiment

Private decision brief · September 6, 2026

**Deferred optional player experiment; not a project-wide blocker or an owner data-gathering task.** Reopening requires a repeatable source for a historical pregame player population with independently resolvable participation and receiving-yard outcomes. The existing 47-file capture is complete; downloading it again or testing a more elaborate model would not fix the missing evidence.

The prior audit's lagged active-WR population covered only **83.78% of targets and 84.74% of receiving yards**, below the frozen 95% thresholds. It left **7,871 of 36,333 outcomes unknown (21.66%)**, above the 1% ceiling. No historical Tuesday population completeness was demonstrated. These are retained audit findings, not a fresh re-audit of all 415 MB.

## Smallest useful source question

For a historical regular-season game, can a source provide all WRs on the relevant team's roster **as known by Tuesday 07:30 America/Los_Angeles**, with the original issue time and later corrections preserved separately, plus independent postgame evidence distinguishing played-zero, played-nonzero, inactive/DNP and unknown?

A useful sample contains these fields or documented equivalents:

| Evidence | Required contents |
|---|---|
| Pregame membership | Season, week, game ID, team, stable player ID, historical position/status, source publication time, original snapshot/version, effective time and capture time where available |
| Population completeness | Which roster categories are included/excluded; how elevations, transactions and newcomers are represented; proof that a missing row has a defined meaning |
| Postgame labels | Same player/game identity, participation evidence, targets and signed official receiving yards, including lateral attribution; explicit zero, DNP, cancellation and unknown rules |
| Identity and revisions | Supported GSIS/PFR crosswalk, unresolved mappings, corrections and the time each version became available |
| Availability and use | Seasons covered, raw-file/sample access, archive retention, and permission for local evaluation and any later public derived output |

Start with one documented game sample to reject an unsuitable source cheaply. A promising sample is only a source-capability check. It does not meet the existing ten-season population gate or authorize fitting; freeze any expanded acquisition and admission protocol before using additional data.

## Reopening criteria

Reopen when a documented API or existing versioned bulk archive supports automated retrieval, deterministic validation and replay at a bounded cost. Use one representative sample to test the actual adapter and schema before larger acquisition. Reject a proposed routine that depends on emailed files, recurring manual exports or human reconstruction of missing rows. Current-week fantasy projections, latest rosters and lists of eventual stat producers cannot establish the required historical population.

If no such archive is available, keep the branch deferred while independent team, market and reliability work continues within its own scope. The owner-approved documentation-only Sportradar inquiry was sent September 6, 2026. It is a one-time capability check; no recurring follow-up or manual data collection is part of the execution plan. No provider has been selected and no new data acquisition or capture is running.

The separate 5% team-model comparison also needs originally timestamped external forecasts, version and usage evidence, and native joint-score output or a preregistered named adapter. The two supplied websites remain source leads, not admitted evaluation data.

The subsequent [official-provider capability screen](player-source-capability-screen.md) narrows the next step: exclude SportsDataIO's standard archive as a solution to historical pregame membership; retain Sportradar as a participation-label lead with unresolved roster-vintage evidence. The documentation-only inquiry was sent and is awaiting an answer. No subscription or bulk acquisition is selected.

This requirement belongs to the frozen player experiment. It is not a prerequisite for the existing team model, the working odds-refresh control or a separately scoped historical market benchmark. The Odds API paid plan supplies market prices rather than the historical player-population and outcome evidence described here.
