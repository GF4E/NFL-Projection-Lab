# Initial chronology release admission — before implementation

The verified restored consumer is operational evidence, not approval to migrate training or transfer control authority. Build a read-only preflight and one hash-pinned packet for both reviewers before the first live transition. No new candidate, parameter, statistical gate or population is introduced.

Tier 1: bind the exact recovery acceptance and consumer bytes, recovered issuing source files, unchanged parent fit/calibration, Linux training ledger, replay history and public-closeout proof. Recheck actual installed issuing files, active fit, external native dependencies, and the accepted full-runtime manifest when supplied privately. Any mismatch refuses qualification. A version string, counts alone, an unverified JSON status or copying success is insufficient.

Tier 1: report each prerequisite separately. A runtime check not performed is NOT_CHECKED, never PASS. Reviewer responses remain external evidence; software may bind their bytes to this packet but cannot authenticate an author's identity from a self-declared name. No local agent-generated approval, synthetic test decision or silence is a real review. Do not create an activation shortcut.

Tier 2 items to present together: preserve target-week blending with fixed cutoff observations; historical availability and refit-finish assumptions; source-qualified bootstrap after collection; rebuild revised observation sets chronologically; reconstruct pre-activation training rather than mix old methods; limit the first live transition to the verified same-code compatibility boundary while retaining full recovery requirements. Include the alternatives and numerical sensitivity evidence already computed. These are existing flags, not newly discovered Tier 3 questions.

The preflight does not fit, publish, install configuration, switch a release or change the series registry. Once genuine review evidence resolves the packet, the next increment must enforce it in the initial operator transition and verify the actual host/public result; a read-only report alone does not complete release admission. Keep this boundary explicit in STATUS and the requirements map.

Validation: changed or forged recovery bytes, wrong source/fit, missing native checks, missing reviews and mutated packet references fail or remain blocked. On the current host, run the read-only preflight and publish its exact named shortfalls. Independent infrastructure work continues while review is pending.
