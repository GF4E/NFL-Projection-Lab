# Durable calibration execution and report plan

Preparation/fixtures only; do not start a real registration or fit a real calibration candidate. The previous increment supplies the guarded numerical worker. This increment retains its attempts and results, supports safe post-result recovery and renders a report without fitting.

One local nonblocking research-worker lock protects all E-CAL registrations. Acquire it before inspecting an unfinished attempt. Pin one immutable request per registration hash; reject changed payload under the same key. Write a durable start before invoking the worker. Store result bytes immutably, then a terminal receipt. A retained valid result can be sealed after a lost response without another fit. A start without a result, observed after acquiring the exclusive lock, is INTERRUPTED, not silently retried. Explicit retry permits a new numbered attempt under the same preregistration; retain all failures, never rewrite the earlier attempt. Do not infer liveness from a stale JSON file. These are local-process semantics; distributed ownership/host deployment remain unqualified.

CONVENTIONS: Tier 1, immutable storage uses the existing fsync/create-if-absent implementation. Tier 2 REVIEW REQUESTED: at most three explicit execution attempts, reusing the weekly runner's conservative execution cap; alternative is retrying until the experiment deadline. This is an operational retry ceiling, not another candidate, statistic or gate. A changed candidate/configuration needs a new registration, not a retry. Neither failed admission nor a report command may trigger fitting. No automatic retry is installed here.

Reports read hash-verified retained results and requests. Render pooled/annual accuracy, uncertainty, all six calibration coverage/interval-score checks, point invariance, calibration execution identities and missing prerequisites. Include the existing two diagnostic-only reference lines using a separately retained diagnostic snapshot, never entering scoring. Draft reviewer packet contains questions and evidence links; no communication or approval is fabricated. Completion of a numerical result is not completion of the registered gate/reviews or clock decision. Historical reports remain readable after the operational clock expires.

Fault tests: duplicate invocation, active lock, changed request, worker exception, crash after durable result/before receipt, uncertain receipt commit, interruption before a result, explicit retry cap, changed result bytes, report regeneration without fitting, report hash/content and named missing evidence. An inability to write on a full disk remains a real failure, not an invented durable success. External runtime/memory supervision, actual historical qualification and installed host execution remain required.

Tier 1 resource convention: executable numerical runs use the existing Linux hard address-space limit of 4 GiB, one numerical-library thread, and GNU timeout's 2,700-second process-group deadline. The CLI refuses execution without those installed Linux tools. Report generation has no fit/supervisor path. A disposable Linux fixture canary will qualify this boundary, not the real historical workload or production-deadline scheduling. Runtime code identity includes the execution module, durable storage primitive and CLI before registration. The three-attempt policy is an explicit field of the future hashed registration. No historical run is registered by these fixtures.
