## Contract

For each upcoming game, select its exact scheduled cutoff strictly before its T75 once that cutoff is due. A newer current pointer does not override that requirement. Missing or unacknowledged required state stops preparation rather than falling back to an older final forecast. Before the future required cutoff exists, the latest completed available state may produce a PROVISIONAL preview. Closed games and existing locks are not prepared again.

Scheduled selection requires the worker's immutable COMMITTED operation-history receipt, not merely state.created_at. The latter is an execution-start clock. Retain the exact worker configuration with its hash; bind the operation/configuration references and completed_at into each prepared row and forecast's state lineage. Before scoring and first lock, reconstruct the features and this availability evidence together. Missing/tampered acknowledgments or a completion later than preparation fail. No historical completion timestamp is invented.

All state/role groups use one captured source schedule, active fit and stadium snapshot. Strength inputs resolve from each selected state's earlier observation reference; a newer team-statistics capture in the current manifest is not assimilated merely by reading that manifest. Immutable group records can be staged, but the prepared pointer commits once, only after all groups succeed. A fixture fails specifically on the second group after the first record exists and proves the original pointer stays intact. Unchanged preparations retain their original clocks and pointer. Once scheduled selection is declared, neither the default legacy preparer nor manual state selection is an allowed silent fallback; compatible rollback remains a separate operation.
