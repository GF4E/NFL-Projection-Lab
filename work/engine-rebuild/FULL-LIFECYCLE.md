# Captured-data lifecycle qualification

This is operational simulation, not a statistical experiment or live activation. It uses the actual weekly entry, retained training-ledger validation, ridge refit, staged scoring, journaled release switch, actual publisher, original forecast bundles, lock/grade readers and board evidence producers. The training reader and numerical engine are not mocked.

The local run passes with all 2,927 training games / 5,854 team rows and all 16 upcoming Week 3 games. One Thursday forecast uses the Tuesday state, fourteen Sunday forecasts use the Friday state, and one Monday forecast uses the Monday state. All sixteen forecasts lock before synthetic finals are added. The release then rolls back to the parent fit; every game still grades from its original forecast bundle. Repeating the weekly entry performs no numerical refit, and duplicate grading preserves first-grade and lock hashes. All 52 original source lock/grade files retain their bytes.

Simulation boundaries are explicit: the captured inputs arrived after Tuesday's cutoff, so a separate isolated observation ledger supplies simulated first-seen timestamps. The Tuesday state/closeout acknowledgment, HTTP response and future clocks are fixtures. Future finals are 20 away / 27 home and enter only after all locks; no synthetic result enters a feature, fit or state. These receipts stay in the disposable root and are never substituted for original availability evidence. The input source bytes, training ledger and upcoming game schedule are retained real data. Historical migration still has its disclosed availability assumptions and review requirement.

### Storage intervention

At the end of the host run, root free space was 1,929,216 bytes, down from approximately 72 MB before the run. The simulation's files were confined to tmpfs, which returned to its initial usage on exit. Inspection found 73 partial APT index downloads totaling 68,270,447 bytes, all with change timestamps between 05:21:04 and 05:21:20 UTC, during the run. The package job was no longer running. Under the held APT lists lock, only the verified Ubuntu mirror/security partial .gz/.xz index files were removed; no installed package or NFL record was touched. Archived system/user journals were rotated and vacuumed to an 8-MiB archived-log budget, freeing 17.3 MiB. Exact cache filenames and before/after capacity are in storage-recovery-lifecycle.json; journal filenames are in storage-journal-vacuum.txt. Latest post-cleanup root free space: 86,196,224 bytes. This remains temporary relief and does not satisfy durable capacity or authorize storage spending.
