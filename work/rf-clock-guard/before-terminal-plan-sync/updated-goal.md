## Test, learn and improve

For each substantive change, state a falsifiable hypothesis, the cheapest meaningful test and a cost limit. Run focused regressions during development, test the real handoff between components before expensive work, and use preregistered chronological backtests for model changes. Record what the evidence tells us to retain, improve, reconstruct, simplify, remove or stop.

Count preparation, validation and maintenance costs as well as execution time, memory and expensive calls. Reuse valid evidence for unchanged dependencies. Engineering optimizations must preserve scientific outputs; a faster implementation is not evidence of better predictions.

Use existing source → forecast → score dependencies for graph engineering first. A small graph can help identify missing evidence, affected tests, duplicate work and bottlenecks when it demonstrates a net benefit. Time-index team states to prevent later outcomes leaking into earlier forecasts. Predictive graph features need their own chronological tests and removal comparisons. A graph framework is not a prerequisite.

Preserve issued predictions. Later outcomes may update ratings under frozen rules; tuning after observing a week cannot turn revised forecasts for that week into out-of-sample evidence. Structural changes require new preregistration. Short rolling Brier scores are descriptive diagnostics, not automatic retuning gates.
