# RF-COMP-03 design review

Decision: the proposed one-entry, per-fit byte-encoding memoizer can preserve recovery authentication, subject to explicit call-site isolation and exact-input qualification. This is design acceptance for a bounded candidate only, not implementation, numerical equivalence, speed or historical authorization. No numerical calls or tests were executed.

Actual call path inspected: `research_score_split_forecast.resolve` creates a fitted descriptor with `research_score_run.distribution_descriptor`, crosses strict JSON, calls archive `recover_source_law`, then independently encodes the recovered descriptor and compares the complete strict descriptor. Archive recovery calls `research_score_run.recover_distribution` (not the stricter conditional-admission `recover_original`). The original recover_distribution recomputes mapper.components(theta), hashes encoded recovered alpha, checks beta/rates, constructs a law, and checks recovered mean/covariance. All these operations and existing error messages must remain. The three large encodings are fitted alpha, freshly recovered alpha, and recovered-descriptor alpha. The original encoder is indent=2, sort_keys=True, allow_nan=False JSON plus a newline, encoded to bytes.

A cache hit is safe only when its key is computed from the current freshly recovered alpha values, not from theta, mapper, saved alphaSha256, ndarray identity, length alone, numerical closeness or Python float-tuple equality. Exact big-endian IEEE754 bytes of every element plus unambiguous length constitute an injective key within the guarded domain. Fixed eight-byte concatenation already determines length; explicit length is harmless. Full byte equality avoids a new hash-collision assumption. In particular, +0.0 and -0.0 must remain different keys. The saved SHA check still runs on every recovery; this optimization reuses a pure function result, not a successful authentication verdict. Existing SHA-256 assumptions are unchanged.

Minimum implementation constraints:

- Only exact built-in list containing exact built-in finite floats enters the fast path. Reject bool/int/np.float64, nested values and subclasses to the unchanged original encoder, preserving its own supported-input and error semantics. Capture one immutable tuple snapshot first and validate/key that same snapshot. Never retain the caller's mutable list as the cached key. On a miss encode a plain-list copy of that snapshot through the pinned original encoder so key and bytes cannot describe different observations. Define ordinary synchronous call semantics; concurrent mutation is not a newly promised guarantee.
- Cache only immutable successful bytes, and commit the new entry only after original encoding succeeds. Do not cache exceptions, normalize signed zero, synthesize JSON, truncate arrays, catch-and-retry errors or mutate descriptors. Unsupported calls must receive their original input unchanged. Specify whether unsupported calls clear the entry; either policy preserves values, but tests/count expectations must match the declared one-entry policy.
- Create the memoizer inside one fit callback and discard it at exit, including fallback/error exits. Avoid global monkeypatching `research_score_run.encoded` or `research_score_contract.encoded`: per-fit state alone does not make process-global rebinding safe. Prefer explicitly scoped local callables with original encoder bound once and unchanged original functions available for qualification. Preserve strict JSON, SHA computation, beta/rate/moment checks and full roundtrip comparison.
- Pin serializer source, Python/runtime and candidate wiring. Reusing bytes is valid only for the same encoder configuration; do not share entries across encoders or fits. Immutable bytes sharing is harmless; no mutable result alias is introduced. Resource failures during snapshot/key allocation remain a practical limit rather than a promise of universal exception identity under exhausted memory.

Required corruption and equivalence probes: independently alter one recovered-alpha element while descriptor hash remains unchanged (including last element, length change and signed-zero change); alter saved alphaSha256 alone; corrupt beta/rates/mean/covariance and confirm original failures remain; spy that mapper.components and digest/check operations still execute on cache hits. Test equal fresh lists hit, mutation after the first call misses, changed then restored content, one-entry eviction, no cross-fit reuse, empty list, subnormal/large finite values, nonfinite and subclass fallback, original-encoder exceptions and successful-entry commit ordering. Compare complete descriptor bytes, recovered-law fields and callback failure class/message against the original path. The helper alone does not qualify integration.

Efficiency limits: snapshotting, exact-type/finite scanning and struct packing remain linear work and memory; three JSON encodings becoming one does not imply a 34–38% whole-fit improvement. Measure the complete registered fit/recover/descriptor callback, then the existing paired fit-plus-score cost with all guards and verification included. Preserve RF-COMP-02's terminal evidence and fixed threshold; do not treat this proposal as permission to relax the criterion or restart RF-02F.
