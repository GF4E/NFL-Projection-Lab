## Existing helpers and their precise limits

- `research_score_conditional_admission.py::Archive`, `parse`, `bound` provide indexed regular-file reads, hash/length validation, duplicate-key/nonfinite JSON rejection and canonical object-pointer checking. `Archive.verify_all(budget)` streams all indexed bytes; do **not** invoke it for this interface task. The controller still owns exact physical membership/terminal acceptance and complete prior compute-chain admission; `Archive` alone is not that entire trust chain.
- `research_score_compute_run.py::preflight` authenticates the accepted original compute/runtime/source/qualification chain without starting a replay. Its accepted context can be matched against the parent manifest. Do not call `build_runner().run` or modify its computation-only AST adapter.
- `research_score_contract.py::prepare_origin(records,origin,delay)` reproduces sorted eligible prior rows using strict availability-before-origin, original target contexts and input/target hashes. Retain the complete receipt in controller provenance, pass only history/targets to the bank. Both histories contain `HistoricalResult` objects; targets are outcome-free `GameContext` objects.
- `conditional_admission::_source_manifest` validates original RF-01/data/config27-source/runtime bindings but **not by itself the entire RF-02C compute receipt chain**. It provides admitted records/origins and original config. The original RF-01 acceptance is the authoritative admitted-data path source.
- `conditional_admission::validate_lineage` adds exact six-node semantic-body checks to `contract.verify_ancestry`; call it for both delays at forecast-bearing origins. Generic graph validation alone is insufficient. Bind the state file separately by its indexed hash.
- `conditional_admission::validate_selected_rows` expects the complete ORIGINAL40-series rows and losses, not a prefiltered six-reference subset. Validate before projecting to reference/E2/N0 sources. `validate_requested_mean` checks original selected native-mean/noise provenance on native successes; validate failures/fallback equality separately. It is not an unselected-diagonal checker because it requires original annual selection equality.
- `conditional_admission::validate_selection` expects all original four families and43 setting populations. The least bespoke reuse path is to keep compact `(season,game,family,setting)→(energy,failure)` tuples for the156,821 original2011–2024 rows, reproduce all13 selections with this helper, then retain only32,823 E2 tuples/pointers and discard temporary control tuples. Alternatively an E2-only wrapper must reproduce the same original nine-setting mathematics explicitly; passing an E2 subset directly to the existing helper fails its contract.
- `conditional_admission::validate_mapper` validates schema, input hash, support and basic numeric bounds, but it returns the **legacy JointBase** and does not recompute exact empirical weights/b from the eligible rows. Do not inadvertently call its legacy solver. For full payload-equivalence checks, compare the original `JointBase.from_scores` construction from unchanged eligible rows/weights, without invoking fit; new fitting must use `research_score_successor_distribution.JointBase`.
- `conditional_admission::recover_original` is strict saved-component recovery with no solver, but requires `type(mapper) is` the legacy class. Use a legacy mapper only for this recovery path, or use `research_score_run.py::recover_distribution` with the already validated descriptor and accepted successor mapper. The latter is duck-typed and needs its surrounding strict schema/pointer validation. Successor JointBase overrides only fit, not components; never call legacy fit. `validate_independent_source` can check original full versus independent descriptor identity.
- Do not call `conditional_admission::admit_archive`: that is the RF-02D20-series/case-construction workflow, not a minimal RF-02F metadata interface. No conditional calibration case construction or parameter receipt is needed here.

## Strict selection and row boundary

`SplitSelectionHistory` inherits `SelectionHistory.add/select` without stricter types. Before add: require exact int season2011..2024, exact int setting0..26, exact family string E3, nonempty game string matching that admitted origin/year, finite native int/float energy>=0 **excluding bool**, and an exact bool failure flag derived only after validating null/nonempty-string native reason. Do not let bool act as setting0/1, float season equal an integer, a string failure become truthy, or an unknown game enter history. Reject duplicate/missing setting/game keys before mutation.

Before select: require exact int outer year2013..2025, complete original expected game universes, a fixed config matching the accepted27-setting registry and the exact two prior seasons. `innerScoreSeasons:[2011,2024]` denotes inclusive bounds under the protocol. Freeze the result before that year's first engine advance; validate result schema/types and choice/candidate order. The base selector's cached-choice return must not conceal a changed universe/config. A no-eligible choice is null plus registered failure/fallback for every variant; do not silently use setting0.

## Minimal reuse decisions

For an E3 ordinary diagonal, reuse selected E2 law/metrics only on exact setting,variant,game,origin,delay and failure/flags agreement. Add actual80% mass as separately recorded CDF-derived data on the authenticated same law/interval. For a different diagonal, recover its full-setting law but compute a complete outer score; derive missing variant laws from that exact candidate's native output. Zero-rate/off-diagonal outputs use their own laws. Shared-variant N0 fallback matches its variant and12/24 delay; O/D and zero-rate removals use full N0. Persist exact native reasons and fallback descriptors; never treat fallback as a native success.
